## Шаг 1 — установка и настройка

```bash
npm install -g harnessed && harnessed setup
```

Это устанавливает harnessed глобально и выполняет разовый онбординг: Agent Teams включены, workflow skills установлены, базовые манифесты обработаны. Что делает каждый шаг — см. [Установка](/ru/docs/getting-started/installation/).

## Шаг 2 — откройте Claude Code

Откройте Claude Code в любом каталоге проекта. Слеш-команды уже доступны глобально — находиться в конкретном проекте не нужно.

## Шаг 3 — запустите первую команду

Введите в Claude Code:

```
/auto research how to add OAuth to my Express app
```

Или начните с конкретного требования:

```
/auto "добавить rate limiter в наш Express API — 100 запросов в минуту на IP, на Redis"
```

## Что произойдёт дальше

`/auto` — это super-master команда harnessed. Она прогоняет весь конвейер из 6 стадий:

| Стадия | Что делает |
|--------|-----------|
| **① Research** (условно) | Многоисточниковое исследование через Tavily, Exa, ctx7 — срабатывает, если вы ответили «нет» на проверку понимания |
| **② Discuss** | Трёхслойные gate прояснения: стратегический охват, решения фазы, неоднозначность подзадачи |
| **③ Plan** | Ревью архитектуры (условно) + сохранение `task_plan.md` и `progress.md` в `.planning/` |
| **④ Task** | Последовательный цикл на подзадачу: прояснить → написать → протестировать → сдать, с TDD в основной логике |
| **⑤ Verify** | 7 условных подпроверок: прогресс, code review, параноидальное ревью, QA, безопасность, дизайн, упрощение |
| **⑥ Retro** | Обязательное резюме вехи — выводы записаны, решения зафиксированы |

`/auto` прогоняет все стадии подряд. Если стадия падает, harnessed останавливается, и вы продолжаете командой `harnessed resume`.

Для тонкого контроля вызывайте стадии по отдельности: `/discuss`, `/plan`, `/task`, `/verify`. Практическое прохождение — в разделе [Первый workflow](/ru/docs/getting-started/first-workflow/).
