## ขั้นที่ 1 — ติดตั้งและตั้งค่า

```bash
npm install -g harnessed && harnessed setup
```

คำสั่งนี้ติดตั้ง harnessed แบบ global และรันการเริ่มต้นใช้งานรวดเดียว: เปิด Agent Teams, ติดตั้ง workflow skills, ประมวลผล manifest พื้นฐาน ดูรายละเอียดแต่ละขั้นได้ที่ [การติดตั้ง](/th/docs/getting-started/installation/)

## ขั้นที่ 2 — เปิด Claude Code

เปิด Claude Code ในไดเรกทอรีโปรเจกต์ใดก็ได้ ตอนนี้คำสั่งสแลชใช้ได้แบบ global แล้ว — ไม่จำเป็นต้องอยู่ในโปรเจกต์ใดโปรเจกต์หนึ่ง

## ขั้นที่ 3 — รันคำสั่งแรก

พิมพ์สิ่งนี้ใน Claude Code:

```
/auto research how to add OAuth to my Express app
```

หรือเริ่มจากความต้องการที่ชัดเจน:

```
/auto "เพิ่ม rate limiter ให้ Express API ของเรา — 100 req/นาที ต่อ IP ใช้ Redis"
```

## จากนั้นจะเกิดอะไรขึ้น

`/auto` คือคำสั่ง super-master ของ harnessed มันรันไปป์ไลน์ 6 ขั้นทั้งหมด:

| ขั้น | ทำอะไร |
|------|--------|
| **① Research** (มีเงื่อนไข) | สืบค้นหลายแหล่งผ่าน Tavily, Exa, ctx7 — ทำงานเมื่อคุณตอบ "ไม่" ในการเช็กความเข้าใจ |
| **② Discuss** | gate ทำความชัดเจน 3 ชั้น: ขอบเขตเชิงกลยุทธ์, การตัดสินใจระดับ phase, ความกำกวมของ subtask |
| **③ Plan** | รีวิวสถาปัตยกรรม (มีเงื่อนไข) + บันทึก `task_plan.md` และ `progress.md` ลง `.planning/` |
| **④ Task** | วนตามลำดับต่อ subtask: ชี้แจง → เขียนโค้ด → ทดสอบ → ส่งมอบ พร้อม TDD สำหรับตรรกะแกนกลาง |
| **⑤ Verify** | ตรวจย่อยแบบมีเงื่อนไข 7 รายการ: ความคืบหน้า, code review, รีวิวแบบระแวง, QA, ความปลอดภัย, ดีไซน์, การทำให้เรียบง่าย |
| **⑥ Retro** | สรุปหมุดหมายแบบบังคับ — เก็บบทเรียน บันทึกการตัดสินใจ |

`/auto` รันทุกขั้นต่อเนื่องกัน ถ้าขั้นใดล้มเหลว harnessed จะหยุด และคุณรันต่อได้ด้วย `harnessed resume`

หากต้องการควบคุมละเอียด ให้เรียกแต่ละขั้นแยกกัน: `/discuss`, `/plan`, `/task`, `/verify` ดูการลงมือทำจริงได้ที่ [workflow แรกของคุณ](/th/docs/getting-started/first-workflow/)
