## หลักการ

ข้อกำหนด R8.1 ของ harnessed ระบุว่า: วงจรการพัฒนาของโปรเจกต์เองต้องใช้ workflow ของตัวเอง ทุกฟีเจอร์ที่ปล่อยใน harnessed ถูกสร้างด้วยจังหวะ `/discuss`, `/plan`, `/task`, `/verify` ชุดเดียวกับที่ harnessed เปิดให้ผู้ใช้

นี่ไม่ใช่คำขวัญ แต่เป็นด่านที่แข็ง workflow ที่ harnessed ใช้ปล่อยตัวเองไม่ได้ คือ workflow ที่ใช้ไม่ได้

## มันจับอะไรได้บ้างในทางปฏิบัติ

ระหว่าง Phase 3.5 W2.1 Cycle 4 ทีมกำลังรัน `/auto` บน repo ของ harnessed เองเพื่อพัฒนาฟีเจอร์ orchestration ใหม่ มีบั๊กโผล่ขึ้นในตรรกะลำดับ spawn ของ `masterOrchestrator`: subworkflow ถูกเริ่มต้นผิดลำดับ ทำให้ขั้น task เริ่มก่อนที่ขั้น plan จะเขียน `task_plan.md` เสร็จ

บั๊กนี้ถูกจับได้ในฐานะการถดถอยจาก dogfood — มันไม่โผล่ในยูนิตเทสต์ เพราะเส้นทางการทำงานร่วมนั้นจะถูกรันก็ต่อเมื่อการรัน `/auto` จริงไป spawn agent เพราะ harnessed ใช้ตัวเอง ความล้มเหลวจึงปรากฏทันทีและชัดเจนไม่มีข้อโต้แย้ง

การแก้ถูกยกเป็น P0 เพราะมันละเมิดข้อตกลงเรื่องความไว้วางใจ: ถ้า harnessed เรียบเรียงการพัฒนาของตัวเองไม่ได้ ผู้ใช้ก็ไว้ใจให้มันเรียบเรียงงานของพวกเขาไม่ได้

## นัยเชิงปฏิบัติ

**การเปลี่ยน schema ตรวจสอบตัวเอง** เมื่อ harnessed เพิ่มฟิลด์ใหม่ใน schema ของ manifest วงจรการพัฒนารอบถัดไปจะใช้ schema นั้นตรวจ manifest ของ harnessed เอง — อัตโนมัติตอน `harnessed install` และใน CI ผ่าน `scripts/check-workflow-schema.mjs` การถดถอยของ schema จะโผล่ในรอบ dogfood ก่อนไปถึงผู้ใช้

**workflow ใหม่ถูกทดสอบภาระก่อน** ก่อน workflow ใดจะถูกปล่อย มันจะถูกรันบน repo ของ harnessed เองเสียก่อน โค้ดเบสเดียวกันที่นิยาม workflow นั้นทำหน้าที่เป็นแท่นทดสอบไปในตัว

**บั๊กจาก dogfood คือ P0** ถ้ารัน harnessed บน harnessed แล้วพัง นั่นคือเหตุการณ์ระดับ P0 ไม่ใช่ข้อจำกัดที่รู้อยู่แล้วซึ่งเอาไว้เขียนในเอกสาร สิ่งนี้สร้างแรงจูงใจอย่างแรงให้เครื่องมือทำงานได้ครบตั้งแต่ต้นจนจบ ไม่ใช่แค่ผ่านยูนิตเทสต์

## สิ่งนี้หมายถึงอะไรสำหรับผู้ใช้

เมื่อคุณรัน `/auto` บนโปรเจกต์ของคุณ คุณกำลังรันไปป์ไลน์เดียวกับที่ใช้ปล่อยตัว harnessed เอง แรงกดดันต่อเนื่องจาก dogfooding หมายความว่า:

- การถดถอยโผล่ระหว่างพัฒนา ไม่ใช่ในรายงานของผู้ใช้
- กรณีขอบของการประสานงานหลาย agent ถูกรันจริงในทุกรุ่นที่ harnessed ปล่อย
- จังหวะ 5 ขั้นผ่านสนามจริงบนโค้ดเบสที่มีอยู่จริงและถูกดูแลอย่างต่อเนื่อง
